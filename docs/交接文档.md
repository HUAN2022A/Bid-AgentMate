# Bid-AgentMate 交接文档

> 更新：2026-09-23。本文档面向接手开发的工程师，覆盖系统全貌、两大产品模式、关键机制与运维注意事项。功能设计细节见 `docs/showcase/`（起草模式四篇）与各提交说明。

## 一、系统是什么

AI 辅助标书编写系统，围绕「一份招标文件」工作，两种产品模式并存于同一个项目列表：

| 模式 | 定位 | 流程 |
|---|---|---|
| **draft 起草模式** | 招标文件 → AI 从零起草标书 | 上传招标文件 → LLM 解析（评分点/技术要求/废标条款）→ 大纲设计确认 → 逐章 AI 起草 → 自查（覆盖矩阵）→ 导出 docx |
| **workbench 工作台模式** | 已有投标文件 → 润色/检查/评分 | 上传招标文件+投标文件（支持 .doc）→ 双侧解析（招标 LLM 拆解 + 投标章节树提取）→ 目录确认 → 润色 / 检查 / 技术模拟评分 |

技术栈：FastAPI + SQLAlchemy 2 + Celery(可选，SYNC_TASKS=true 免依赖) + sqlite(开发)/PostgreSQL(生产)；React 19 + Vite + AntD 6 + TanStack Query + TipTap v3。正文统一以 markdown 存储。

## 二、启动

```bash
# 后端（backend/）——本地开发
cp .env.example .env   # 首次；填 LLM__API_KEY 等
uv run uvicorn app.main:app --port 8000
# 样例模式（无 LLM key 也能演示工作台全流程）
SAMPLE_MODE=true SYNC_TASKS=true uv run uvicorn app.main:app --port 8000

# 前端（frontend/）
npm run dev   # 5173，/api 代理到 8000
```

- 账号：首次启动自动建 `admin/admin123`
- 数据：sqlite `backend/data/dev.db` + 文件 `backend/data/`（均已 gitignore）
- **建表**：新表自动 create_all；**对已有库加列须跑一次** `uv run python scripts/migrate_workbench.py`（幂等）

## 三、工作台模式关键设计

### 状态机与数据
- `projects.mode`（draft/workbench）；工作台状态：`created → wb_parsing → wb_parse_failed | wb_outline_pending → wb_ready`，之后润色/检查/评分不占主状态
- 投标文件挂 `tender_files.role='bid'`；目录树存 `outline_drafts/snapshots`（`doc_kind='bid'`，叶节点带 `content_md`）
- 确认目录 → 物化 `chapters`（state=imported）+ `chapter_versions`（source=imported）；润色采纳产生 ai_paragraph 版本

### .doc 转换（doc_converter.py）
soffice 优先 → Word COM（pywin32，Windows+Office）→ 报错提示另存 .docx。116MB 真实文件实测 7 秒。Linux 部署装 LibreOffice 即走首链。

### 投标解析（bid_parse_service.py）
docx 标题层级（outlineLvl + Heading 样式）→ 层级栈切树（自动规整 ## 直跳 ####），零 LLM；无结构时 LLM 兜底（anchor 逐字回对）。真实文件验证：163 章/12.7 万字。

### 检查机制（workbench_check_service.py + api/workbench.py）
- `check_runs` 行级状态（running/done/failed + 分块进度），重跑生成新 run、历史保留
- `findings` 八字段 + 人工确认流（属实/误报/已修复，PATCH 记录确认人）
- 四类检查：废标项（条款逐条裁决，pass 进统计）、错别字（~3000 字分块全书扫，**LLM 片段逐字回验**，不命中即弃）、逻辑谬误（逐章）、技术评分（逐评分点估分 → `score_estimates`，重新估分保留手工修正）
- 触发：按页签手动 + 章节范围可选；SYNC 模式同步执行（全书扫描分钟级）

### 样例模式（SAMPLE_MODE=true）
LLM 环节替换为 `app/samples/` 固定 fixture（招标解析/四类检查/迷你三件套含错别字埋点），项目列表「一键样例项目」走真实上传解析路径。

## 四、LLM 配置（重要教训）

`.env` 关键项：`LLM__BASE_URL/API_KEY/MODEL`（全局）+ 环节覆盖 `LLM__PARSE__*/LLM__DRAFT__*/LLM__COPILOT__*`。

1. **glm-5.3 是思考型模型**：思考计入 max_tokens，预算不足时正文为空（JSON 解析 char 0 失败）。已默认 `LLM__THINKING=disabled`（可按环节开），parse/draft 32k、copilot 16k 预算。
2. Coding 套餐端点 `https://open.bigmodel.cn/api/coding/paas/v4`（OpenAI 兼容；base_url 不含 `/chat/completions`）。
3. **限额**：5 小时窗口，429 时错误信息含重置时间；长扫描建议提示用户。

## 五、已知坑（环境）

- **Windows 孤儿进程**：杀 npm/uvicorn 包装任务不杀子进程——重启服务后行为异常时先 `netstat -ano | findstr 端口` + `taskkill /PID x /F`。
- **vite HMR 不失效**：Windows 下工具写文件偶发不触发 watcher（浏览器一直拿旧模块），已在 `vite.config.ts` 开 `usePolling`。
- **sqlite 并发写锁**：已开 WAL + busy_timeout，且解析/copilot 等长 LLM 调用前提前 commit；生产 PostgreSQL 无此问题。
- IAB 浏览器自动化中 antd 中文按钮文本带空格（「开 始」），定位时用 `textContent.replace(/\s/g,'')`。
